# Документация к API — платформа объявлений «Барахолка»

> ⚠️ Придумано для тренировки. Настоящую документацию выдают на площадке в медиафайлах —
> адреса, поля и тексты ошибок там будут другими. Логика (токен в заголовке, 422 с
> `errors` по полям, WebSocket-событие о новом объявлении) — та же, что требует ТЗ.
>
> Сервер — твой Django-бэк из `../module-c-backend`, запускается на `:4000`.

Базовый URL: `http://localhost:4000`
WebSocket:   `ws://localhost:4000/ws`

CORS открыт для любых источников, так что клиент с `localhost:5173` может ходить
на `localhost:4000` напрямую.

## Авторизация

Токен передаётся в заголовке:

```
Authorization: Bearer <token>
```

## Формат ошибок

| Код | Тело | Когда |
|---|---|---|
| 422 | `{"message": "Invalid fields", "errors": {"email": ["Введите e-mail"]}}` | ошибка валидации |
| 403 | `{"message": "Forbidden for you"}` | гость на защищённом эндпоинте / чужое объявление |
| 404 | `{"message": "Not found"}` | объявление не найдено |

`errors` — объект `имя_поля → массив сообщений`. Именно его надо разложить по
полям формы и подсветить поля.

## Эндпоинты

### POST /api/register — гость
Тело: JSON `{ "email": "...", "password": "..." }`
Ответ: `201 { "success": true, "id": 3 }`
Валидация: e-mail обязателен и должен быть корректным и уникальным; пароль от 6 символов.

### POST /api/login — гость
Тело: JSON `{ "email": "...", "password": "..." }`
Ответ: `200 { "token": "…", "email": "…" }`
Неверная пара: `422 {"message":"Invalid data","errors":{"email":["Неверный e-mail или пароль"]}}`

### GET /api/me — токен
Ответ: `200 { "email": "…" }`

### GET /api/listings — гость и авторизованный
Query: `sort=price_asc` | `sort=price_desc`; без параметра — новые сверху.
Ответ: `200 { "data": [ Listing, ... ] }`

### GET /api/listings/mine — токен
Ответ: `200 { "data": [ Listing, ... ] }` — только свои, новые сверху.

### GET /api/listings/:id — гость и авторизованный
Ответ: `200 { "data": Listing }`

### GET /api/listings/:id/contact — гость и авторизованный
Ответ: `200 { "email": "seller@example.com" }`
Вызывать **только по клику** пользователя — e-mail владельца намеренно не входит
в основной payload объявления.

### POST /api/listings — токен
Тело: **`multipart/form-data`** (не JSON!) — поля `title`, `description`, `price`, `image` (файл, обязателен, ≤ 5 МБ).
Ответ: `201 { "data": Listing }`
Побочный эффект: всем WebSocket-клиентам уходит событие `listing:new`.

### PUT /api/listings/:id — токен, только своё
Тело: `multipart/form-data`, все поля необязательны (что прислали — то и обновится). `image` можно не присылать.
Ответ: `200 { "data": Listing }`; чужое — `403`.

### DELETE /api/listings/:id — токен, только своё
Ответ: `204` без тела; чужое — `403`.

## Объект Listing

```json
{
  "id": 4,
  "title": "Велосипед Stels Navigator",
  "description": "Горный велосипед, 21 скорость.",
  "price": 14500,
  "image_url": "http://localhost:4000/uploads/listings/seed-1.svg",
  "created_at": "2026-09-19 08:12:41",
  "is_mine": false
}
```

`is_mine` считается сервером по вашему токену (у гостя всегда `false`).
`image_url` — уже полный адрес, его можно сразу ставить в `<img src>`.

## WebSocket

Подключение: `ws://localhost:4000/ws`, канал один, подписка и токен не нужны.

Сразу после подключения приходит `{"type":"hello"}`.
При создании любого объявления всем клиентам приходит:

```json
{ "type": "listing:new", "listing": { ...Listing... } }
```

Уведомление должно появляться и у гостей, и у авторизованных, без перезагрузки страницы.
